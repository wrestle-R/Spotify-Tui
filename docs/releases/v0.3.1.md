# v0.3.1

28 October 2026 · **Stable** · Linux x86_64

## Website and safer update restoration

The repository now includes a Next.js website under `next/`. The landing page uses the approved glass music-note logo and a generic terminal screenshot. The setup guide walks through installing the Linux release, browser sign-in, the separate Soloist key and initial device pairing. It explains tray controls, updates, troubleshooting and current limits. The changelog and version detail pages read the repository's Markdown at build time, keeping the website and release documentation together.

The website is a static export. It does not collect Spotify passwords or tokens, and does not require an environment file. It is included as source in the repository, not bundled into the player archive. Run it using the [website instructions](../../next/README.md). No public website hosting is configured by this release.

After updating, playback restoration now keeps the active TUI busy until the play/seek operation finishes, preventing a keyboard command from racing it. The restart position includes elapsed playback time, and `--no-tray` stays respected after restart. The tray and provider-confirmed pause/resume behaviour from [v0.3.0](v0.3.0.md) remain available.

## Install or upgrade

From installed v0.3.0, open the player and press **Ctrl-U** when the stable update is offered. It downloads and verifies the release, installs a matching Go/Rust pair and restarts. The command-line equivalent is `~/.local/bin/spotify-tui update`.

For a fresh install:

```bash
curl -fL https://github.com/wrestle-R/Spotify-Tui/releases/download/v0.3.1/download-linux.sh -o download-linux.sh
less download-linux.sh
bash download-linux.sh --destination ./spotify-tui-031
bash ./spotify-tui-031/install.sh
~/.local/bin/spotify-tui --demo
```

The download is Linux x86_64, tested on Arch, with glibc 2.39+ and libgcc_s. Audio needs separate Soloist setup and a personal key generated by a Premium account. Existing XDG config, keyring and provider data are retained. Both binaries must report `0.3.1` after installation.

## Validation

Go race tests, formatting and vet; eight Rust tests, formatting and clippy. Update regression checks cover playback restoration's busy state, Ctrl-U while searching, checksum failure, unsafe archives, managed installation boundaries and pair activation. Linux package checks exercise download verification, installer upgrades and paths with spaces. The Next.js production build checks types and exports the landing page, docs, changelog and every stable version page. Browser checks cover desktop/mobile layout, navigation and copying setup commands.

Live testing uses the downloaded installation, not `dist`. Detailed results, including the actual v0.3.0-to-v0.3.1 Ctrl-U upgrade, are recorded in [implementation notes](../IMPLEMENTATION.md).

## Known limits

Genuine offline downloads remain unsupported. Search returns ten results; full liked-song sequencing, playlist offsets, MPRIS and long-session memory/stability checks remain unfinished. Provider connectivity/session restoration can stall; `c` restarts it. Updating can interrupt music during helper restart. No ad-free promise for Free accounts. The package is checksum-verified and unsigned. See [v0.3.0](v0.3.0.md#known-limits) for integration details.
