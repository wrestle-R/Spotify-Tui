# v0.2.0

28 October 2026 · **Stable** · Linux x86_64

## Intuitive navigation and a more familiar player

The first packaged Linux release gives the TUI a Spotify-green theme and a clearer keyboard flow. Left/Esc returns to the library, Right/Enter opens collections, and paging follows the focused pane. The README now explains the RAM motivation and shows generic sample music.

[Download Linux x86_64 ↓](https://github.com/wrestle-R/Spotify-Tui/releases/download/v0.2.0/spotify-tui_0.2.0_linux_amd64.tar.gz) · [GitHub release and all files ↗](https://github.com/wrestle-R/Spotify-Tui/releases/tag/v0.2.0) · [Changelog](../../CHANGELOG.md#v020)

## What changed

- **Navigation:** arrows or j/k move, Left/h/Esc returns to the library, Right/l/Enter opens, and Tab switches panes. Page Up/Down and Home/End move in that pane. Scrolling preserves the visible viewport.
- **Smaller terminals:** the focused pane uses the available width; the library remains reachable. Visible focus and selection markers accompany the colours.
- **Playback feedback:** Enter connects the player automatically when necessary. Requests show pending feedback, duplicate submissions are suppressed, and browsing stays available. Reconnect restarts a stalled helper.
- **Search:** cursor movement, Unicode editing, Delete/Backspace, Ctrl-U/Ctrl-W, paste and cancellation. Refresh keeps the original query. Pasting outside a field cannot trigger shortcuts.
- **Appearance:** Spotify green, charcoal background, a selected-row highlight, progress and playback state, and contextual keyboard hints.
- **Try before setup:** `--demo` uses a generic local library. It reads no account data and produces no audio. The screenshot below comes from that mode.
- **Source layout:** `go/`, `rust/`, `scripts/`, `protocol/`, `docs/` and `design/`, with build/test/package commands at the repository root.

## Packages and requirements

| File | Purpose |
| --- | --- |
| `spotify-tui_0.2.0_linux_amd64.tar.gz` | Go TUI, matching Rust helper, local installer and documentation |
| `download-linux.sh` | Download, verify SHA-256, validate and extract into a new directory |
| `SHA256SUMS` | Checksums for the archive and downloader |

Tested on **Arch Linux x86_64**. The Rust helper requires **glibc 2.39+** and `libgcc_s`. Go is built with CGO disabled. Real audio additionally requires Spotify Premium, your own developer/provider setup, Spotify's separately obtained Soloist binary, and PipeWire or PulseAudio. Windows, macOS and Linux ARM packages are not supplied.

The packages are unsigned. Checksums from the same release detect corruption and mismatches; they do not independently authenticate the publisher. The repository is private and requires GitHub access.

## Install

Using an authenticated GitHub CLI in a new working directory:

```bash
gh release download v0.2.0 --repo wrestle-R/Spotify-Tui --pattern download-linux.sh
less download-linux.sh
bash download-linux.sh --destination ./spotify-tui-linux
bash ./spotify-tui-linux/install.sh --dry-run
bash ./spotify-tui-linux/install.sh
~/.local/bin/spotify-tui --demo
```

The downloader does not execute the downloaded application. The installer places a complete pair under `~/.local/lib/spotify-tui/` and links the commands under `~/.local/bin/`. Use `--prefix /your/prefix` on `install.sh` for another location. Complete [account and provider setup](../SETUP.md) to play real music.

## Upgrade from an earlier source build

1. Exit the old terminal UI. Run its `spotify-tui stop` command to stop the old helper before changing versions.
2. Download and verify the release into a new directory, then run its installer with your previous prefix.
3. Run the installed `spotify-tui version` and `spotify-tui-playback --version`; both should report `0.2.0`.
4. Run `spotify-tui --demo` to try the keyboard flow, or launch normally to use your existing configuration.

The installation does not overwrite your XDG configuration, keyring entries or provider data. Old build directories remain available under the install prefix for manual rollback. Keep the matching Go/Rust pair together. If your config explicitly names an old helper path, update it using `setup --helper-path` to the newly installed helper. A config using the default helper name resolves the sibling automatically.

## Known issues

- **Offline music downloads are unsupported.** The evaluated provider has no supported music-download operation; an encrypted playback cache does not satisfy this requirement.
- Soloist can occasionally stall while restoring its stored session. `c` now restarts the helper, but complete recovery across all network/provider failures is not established. A later real search test also encountered a connectivity timeout and displayed the connection error.
- A selected liked song plays individually. Full liked-song sequencing and starting a playlist at a selected offset are not implemented. `P` requests the playlist context from its beginning.
- Search currently returns the first ten results. Spotify can restrict enumerating followed or curated playlist songs.
- Tray integration and MPRIS/media keys are not included. Long-session RAM comparisons and stability verification remain pending.

This release contains the implemented online player. The original offline requirement remains unsatisfied.
