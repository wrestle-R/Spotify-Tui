# v0.4.0

29 October 2026 · **Stable** · Linux x86_64 and Apple Silicon macOS

## A native Mac terminal player

Spotify TUI now builds for Apple Silicon Macs as a matching Go interface and Rust
playback helper. Browser sign-in opens the normal macOS browser, credentials use
macOS Keychain, and local audio uses Spotify's separately downloaded official
Soloist Mac build. The player does not need the official Spotify desktop app to
remain open after provider pairing.

This is an arm64 release, not an Intel Mac release. The macOS support floor for
this release is macOS 15. Native GitHub Actions jobs target macOS 15 and macOS 26;
Linux x86_64 continues to build and test on Ubuntu 24.04. CI checks native versions,
race tests, Rust tests, real Go/Rust socket communication, packaging, installation
and an actual PTY terminal demo. A provider `--version` check verifies its native
executable starts; it does not validate an account or audible playback.

Python 3.9+ is needed for downloading/installing, not for running the TUI. The
portable downloader selects the native archive, verifies its SHA-256 and rejects
unsafe archive entries before extracting. The installer uses a shared update
lock and atomically activates the Go/Rust pair, preserving older builds.

```bash
curl -fL https://github.com/wrestle-R/Spotify-Tui/releases/download/v0.4.0/download.py -o download.py
less download.py
python3 download.py download --destination ./spotify-tui-040
bash ./spotify-tui-040/install.sh
~/.local/bin/spotify-tui --demo
```

Follow [macOS setup](../MACOS.md) for Soloist, sign-in, Keychain and provider pairing.
For an existing managed installation, Ctrl-U or `spotify-tui update` downloads the
matching platform pair. Linux v0.3.x users can use their existing updater.

## Platform fixes

The updater now selects native archive names and validates Linux ELF or Apple
Silicon Mach-O executables before executing version checks. Incorrect platforms
or mismatched versions are rejected. macOS runtime sockets use a shorter private
per-user path, and IPC tests use short temporary paths to respect its socket limit.
Version/help commands no longer create account/runtime directories.

The Linux StatusNotifier tray remains available. macOS runs the terminal player
without a tray; no native menu-bar integration is included. Linux namespace-based
offline probing is explicitly unavailable on macOS.

## Release verification and limitations

All required native matrix jobs must pass before the tagged release is published.
Their archives/checksums are collected and reverified together. Duplicate common
assets must be byte-identical. A missing platform prevents release publication.
See [macOS verification notes](../MACOS.md#verification-boundaries).

The macOS binaries are ad-hoc signed for native execution. They are **not Developer
ID signed or Apple-notarized**; no Apple signing credentials were provided. Respect
Gatekeeper decisions and review the documented limitation before distributing to
users who require notarized software. SHA-256 checksums are unsigned.

No hosted runner can confirm your Keychain consent, Spotify browser verification,
one-time device pairing, speakers or sustained real-account playback. Those require
a real Mac account test, and have not been claimed as completed here.

Genuine offline downloads remain unsupported on both platforms. Full liked-song
sequencing, search pagination, MPRIS and long-session stability remain outstanding. Soloist is never bundled or redistributed in these archives.

## Website and RAM comparison

The site adds a real Linux paused-library [memory comparison](../MEMORY.md), with
the complete TUI process stack and terminal counted, per-group PSS/RSS/swap data,
and a reproducible sampler. It is a short single-machine result, not a Mac benchmark
or a long-session claim. Section reveals and small interactions respect reduced
motion; a page-wide animation control and background/offscreen pausing keep the
site usable without continuous decorative work.
